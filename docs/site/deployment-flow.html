Deployment Flow

Build, publish, pull, verify.

A push to main triggers GitHub Actions. It validates the configuration, builds the application, and publishes a versioned release bundle with SHA-256 checksums.

From release to production

  1. A timer on the VM polls GitHub for a new release using a read-only credential and conditional requests.
  2. The VM checks the release identity and checksums, stages the bundle, and takes a local database backup before applying it.
  3. Docker Compose builds and updates the services. Nginx validates and reloads its configuration. Origin readiness, public routing, and container health are checked.
  4. After the host checks pass, the VM publishes a confirmation with the deployed commit and verification time. GitHub Actions reads /deployed.json over HTTPS and waits up to 15 minutes.

Rollback and operator checks

A failed verification restores the previous release and retains its deployment confirmation. The VM records the failed release and waits for a newer one. To diagnose a deploy, compare the GitHub jobs, the host journal, the deployed commit, and the container health checks.

The VM initiates every release download. GitHub can verify the public endpoint without SSH access to the host.
