Docs / Deployment Flow

Build once, scan, publish, pull, verify.

The production host runs the immutable registry images scanned in CI.

Release and image identity

CI validates source and Compose, embeds the commit, and builds both PHP images once for linux/amd64. Complete vulnerability reports are separate from the blocking critical gate; reports remain available when the gate fails.

Reviewed package exceptions have owners and expiry dates. Relevant fixable CRITICAL findings block publication; HIGH and unfixed findings remain visible for review.

The release manifest records registry and configuration digests, filesystem layers, commit and report checksums. The host verifies the bundle, prepares logical database backups, pulls both digests, and checks identity before changing live files. It does not rebuild normal releases.

Host verification and rollback

The host checks running images against the scanned manifest, tests and reloads Nginx, waits for origin readiness, and checks routing, headers, the static DMA boundary and authenticated Grafana nonce handling.

Only passed host verification changes the deployment receipt. GitHub verifies it over HTTPS for up to 15 minutes. A failed attempt retains the previous receipt and failure history; rollback restores the previous files, images and deployment state.

The host initiates downloads. The workflow needs no inbound SSH access. Host cron jobs, timers and certificate tooling are not installed by deployment.

Explicit emergency path

The former host build remains an explicit operator recovery option, disabled by default. It requires the established full backup, retained previous images and reconciliation of deployment state. It is not claimed as normal CI-image provenance, and a registry failure never selects it automatically.

Recorded verification

On 27 November 2026, release bbd5594 passed the registry-identity, host and public checks. A synthetic fixable critical finding separately proved that the security gate blocks publication while retaining the report. These are recorded checks, not a blanket availability or vulnerability-free claim.
