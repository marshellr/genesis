Docs / Backup

Separate local evidence and encrypted offsite recovery.

Logical database dumps and consistent SQLite copies are prepared before encrypted offsite snapshots. A shared lock prevents the pre-deploy hook and nightly backup from running concurrently.

Backup boundaries

MariaDB is restored from its logical dump. Raw database backing data, duplicate local archive sets and short-lived metrics and log stores are excluded from the application offsite snapshot.

Local archives retain seven complete sets with checksums and manifests; partial artifacts are not promoted. Local dumps, archives, hypervisor backups and encrypted offsite snapshots have separate success evidence. The internal dashboard evaluates local and external freshness independently.

Restore evidence: 27 November 2026

The selected offsite snapshot was 19.66 hours old. SQL was imported into a separate MariaDB instance, application tables were checked and both restored SQLite copies passed integrity checks.

Both PHP applications ran on an internal test network with the restored data and no published ports. HTTP health, the portfolio database adapter and DMA database queries succeeded. Production credentials and data were not changed; temporary data, containers and the test network were removed.

Retrieval, logical restore and application checks took 19.6 seconds on an already available Docker host with the required images. Replacement hardware or VM provisioning, certificate recovery and tunnel restoration are outside this timing.

Recovery objectives and limits

The confirmed recovery point objective is 25 hours. The recovery time objective is 2 hours for complete service restoration to an available replacement VM, assuming working hardware, network and backup credentials.

The measured exercise covers logical data and application startup. It does not establish a complete replacement-infrastructure timing result. Restore to private staging, verify checksums and data integrity, then check configuration, image identity, health and public routing before declaring recovery complete.
