Docs / Lessons

Checks need explicit scope and failure evidence.

The operating model uses immutable artifacts, bounded state and recorded recovery tests.

Artifact identity

Build and scan once, deploy the registry digest and verify the running image and embedded commit. A failed attempt retains evidence and the previous confirmation.

Retention and resource limits

Metrics, logs, images and backup staging need explicit limits. Provisioned capacity and measured filesystem usage are separate signals.

Recovery scope

A data import and an application startup test are useful evidence. Their timing does not measure replacement hardware, a new VM or restored public ingress. Keep those assumptions visible beside the recovery objectives.

Visibility without notification

The internal dashboard shows current evidence and warnings, while Uptime Kuma remains in service during the comparison period. No alert delivery or external notifying monitor is configured. A host, power or Internet failure can remove the dashboard itself; detection depends on the next operator check.
